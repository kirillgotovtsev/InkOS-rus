# InkOS-rus

Русская версия [InkOS](https://github.com/Narcooo/inkos) 2.0.0: рабочая среда с ИИ для романов, рассказов, сценариев, раскадровок, интерактивных историй и перевода длинных текстов.

В этом форке переведены интерфейс Studio, основные служебные сообщения CLI/TUI и документация для пользователей и разработчиков. Добавлены русский язык романа, подсчёт русских слов и работа с русским текстом на этапах планирования, написания, проверки и правки глав.

[Документация](docs/README.md) · [История изменений](CHANGELOG.md) · [Участие в разработке](CONTRIBUTING.md) · [Происхождение и лицензия](NOTICE.md)

Оригинальные руководства: [中文](README.zh-CN.md) · [English](README.en.md) · [日本語](README.ja.md).

## Установка русской версии

Нужны Node.js **22.16.0 или новее**, pnpm **9 или новее** и Git.

```bash
git clone https://github.com/kirillgotovtsev/InkOS-rus.git
cd InkOS-rus
pnpm install --frozen-lockfile
pnpm build
npm run inkos -- init --lang ru
npm start
```

Откройте адрес, который сервер напечатает при запуске. По умолчанию это `http://127.0.0.1:4567`. На странице «Настройка моделей» выберите сервис, укажите ключ API, проверьте подключение и сохраните модель. Кнопка «РУ» в верхней панели включает русский интерфейс.

`npm install -g @actalk/inkos` и `clawhub install inkos` устанавливают исходный InkOS. Русская версия из этого репозитория устанавливается приведёнными выше командами. Отдельная публикация `InkOS-rus` в npm в этот выпуск не входит; имена внутренних пакетов `@actalk/*` сохранены для совместимости сборки.

Для команд из следующих разделов можно задать локальное сокращение. Выполните его в каталоге клона:

```bash
inkos() { node "$INKOS_RUS_HOME/packages/cli/dist/index.js" "$@"; }
export INKOS_RUS_HOME="$PWD"
inkos --help
```

Функция действует в текущем сеансе оболочки Bash или Zsh. Без неё используйте `npm run inkos -- <команда>` в корне репозитория либо абсолютный путь к `packages/cli/dist/index.js`. В PowerShell вызывайте этот файл через `node`.

Рабочие проекты можно хранить отдельно от исходников:

```bash
inkos init my-novel --lang ru
cd my-novel
inkos studio
```

Чтобы обновить форк, остановите его сервер, перейдите в каталог клона и выполните:

```bash
git pull --ff-only
pnpm install --frozen-lockfile
pnpm build
```

Затем запустите Studio снова. Команда `inkos update` относится к каналу обновлений исходного npm-пакета и не служит способом обновления `InkOS-rus`.

## Что поддерживает русский выпуск

- Русский интерфейс Studio и основные сообщения CLI/TUI.
- Явная инструкция модели отвечать по-русски в русском чате; язык произведения задаётся отдельно.
- Выбор `ru` при создании романа и настройке языка проекта.
- Русские основы романа, задания глав, черновики, правки и отчёты о непротиворечивости.
- Целевой объём русской главы в словах; по умолчанию 2 000 слов. Дефисные слова вроде «всё-таки» считаются одним словом.
- Более короткие подписи и перенос элементов интерфейса в узком окне; полный текст длинных названий книг и глав при наведении.

Встроенные 20 навыков `SKILL.md` и их справочники сохранены на языках исходного проекта. Это рабочие инструкции для модели. Перевод документации для людей не меняет эти инструкции. Русская локализация интерфейса также не означает, что все унаследованные режимы рассказов, сценариев и интерактивных миров полностью адаптированы к русскому языку: в части их внутренних путей сохраняется выбор `zh`/`en`.

## Устройство версии 2.0

В InkOS 2.0 чат, TUI, внешние агенты и производственные операции используют общий исполнительный контур на базе pi-agent. Модель понимает запрос, предлагает действия и вызывает возможности программы. InkOS отвечает за подтверждения, контекст, состояние, атомарное сохранение и проверку результата по файлам.

Для перехода с 1.x сначала просмотрите миграцию:

```bash
inkos work migrate --json
```

Применяйте её отдельно, после проверки результата:

```bash
inkos work migrate --apply
```

Миграция преобразует настройки книг, правила и снимки состояния, сохраняя исходные каталоги и исторические значения, для которых нет явного преобразования. Устаревшие настройки остаются в исходных файлах; версия 2.0 использует политики действий профилей. Проекты без состояния выполнения появляются в библиотеке как черновики, требующие восстановления.

В общий исполнительный контур входят:

- Настройка поставщиков, маршрутизация моделей, сервисы обложек, агрегаторы kkaiapi/OpenRouter и собственные OpenAI-совместимые адреса.
- Типизированные действия и результаты для Studio Chat, TUI, `inkos interact` и фоновых исполнителей.
- 20 встроенных профессиональных навыков для разных форматов работы.
- Локальный поиск SQLite FTS5/BM25 по памяти истории, архивным материалам и справочникам навыков. Индекс можно перестроить; исходные файлы остаются источником истины.
- Материалы, явно привязанные к книге с указанием назначения. Поиск выбирает их по задаче, вместо добавления всех файлов целиком в каждый запрос.
- Рабочие области глав: текст, состояние, сюжетные зацепки и снимки выполнения проходят проверку и сохраняются одним атомарным набором файлов.
- Снимки, наблюдения, отмена и восстановление для рассказов, сценариев, раскадровок, интерактивных фильмов, Play и перевода.
- Последовательная работа над несколькими главами в одной восстанавливаемой задаче; ограничения ожидания первого токена и простоя потока.
- Команды TUI `/new`, `/short`, `/play`, `/cover`, `/write`, `/confirm`, `/cancel` и выбор модели сеанса через `/model`.
- Поддержка LM Studio, сохраняемые каталоги моделей, импорт внешнего канона, собственные базовые URL сервисов обложек и рабочая область переписывания главы.

## Режимы творчества

**Роман.** Создание по замыслу автора, подготовка основы, намерения главы и контекста, написание, проверка, правка и обновление состояния. Контекст делится на защищённые и допускающие сжатие слои.

**Прогноз повествования.** Перед следующей главой можно получить 2–5 изолированных вариантов продолжения из текущего канона. В Studio сравниваются события, решения персонажей, предполагаемые изменения, риски и соответствие авторскому замыслу. Выбор сохраняет только `selected-branch-plan.md`: текст, план и каноническое состояние не меняются. После изменения канона прогноз помечается устаревшим.

**InkOS Short.** Подготовка законченного рассказа: полный текст, материалы плана и проверки, синопсис, продающие тезисы, запрос для обложки и, при настроенном сервисе, изображение обложки.

**InkOS Play.** Открытый мир или ветвящаяся история по описанным автором правилам: ход времени, действия персонажей, инвентарь, улики, отношения, состояние сцены, варианты выбора, свободные действия и необязательные изображения.

**Интерактивный фильм или игра.** Преобразование идеи, сценария или прозаического материала в ветвящиеся сцены, переменные, концовки, запросы для изображений, иллюстрации узлов и экспортируемый проект.

**Studio Chat.** Сохраняемый чат для обсуждения, создания книг, запуска Short и Play, генерации обложек и редактирования текстовых материалов. Успех операции определяется результатом инструмента и сохранёнными файлами.

**Навыки и исследование.** Дополнительные пакеты `SKILL.md` можно разместить в `.agents/skills/` или другом стандартном каталоге AgentSkills. `@skill-id` явно выбирает навык. Запрос исследования может создать Markdown-отчёт с источниками.

## Настройка моделей

Studio использует настройки сервисов из интерфейса. CLI, фоновый процесс и серверное развёртывание дополнительно поддерживают переменные окружения и параметры команд.

### Настройка в Studio

1. Откройте «Настройка моделей».
2. Выберите сервис: Google Gemini, Moonshot, MiniMax, DeepSeek, kkaiapi, OpenRouter или собственный совместимый адрес.
3. Введите ключ API и проверьте подключение.
4. Выберите доступную модель, сохраните настройки и вернитесь в чат или книгу.

Studio использует настройки проекта и `.inkos/secrets.json`. Интерфейс может показывать обнаруженные переменные окружения, но env-файлы не подменяют выбранные в Studio сервис, модель, базовый URL и ключ API.

По умолчанию сервер принимает запросы браузера с того же источника. При собственном встраивании или обратном прокси доверенные источники задаются через параметр запуска сервера `allowedOrigins`.

### CLI и переменные окружения

```bash
inkos config set-global \
  --lang ru \
  --provider <openai|anthropic|custom> \
  --base-url <API endpoint> \
  --api-key <your API key> \
  --model <model name>
```

`--lang ru` задаёт русский язык по умолчанию для CLI и фонового процесса. Глобальная конфигурация хранится в `~/.inkos/.env`.

`provider` принимает `openai`, `anthropic` или `custom`; для OpenAI-совместимых прокси используется `custom`. `base-url` задаёт адрес API, `api-key` — ключ доступа, `model` — идентификатор модели.

Глобальный `~/.inkos/.env` или проектный `.env` можно заполнить вручную:

```dotenv
INKOS_LLM_PROVIDER=custom
INKOS_LLM_BASE_URL=
INKOS_LLM_API_KEY=
INKOS_LLM_MODEL=
INKOS_DEFAULT_LANGUAGE=ru
```

Необязательные параметры: `INKOS_LLM_TEMPERATURE=0.7` и `INKOS_LLM_THINKING_BUDGET=0`. Последний задаёт бюджет расширенного рассуждения Anthropic.

CLI начинает с настроек сервиса Studio/проекта, затем учитывает секреты сервиса, глобальное окружение, проектное окружение, окружение процесса и параметры CLI. Поэтому CLI может использовать настроенный в Studio сервис, а env и параметры команды служат явными переопределениями.

### Разные модели для разных агентов

```bash
inkos config set-model writer <model> --provider <provider> --base-url <url> --api-key-env <ENV_VAR>
inkos config set-model auditor <model> --provider <provider>
inkos config show-models
```

Агент без отдельного назначения использует общую модель. Это позволяет выбирать модели по стоимости и требованиям конкретной операции.

### Диагностика подключения

```bash
inkos doctor
```

Команда показывает действующий режим конфигурации, происхождение сервиса, модели и ключа, затем проверяет подключение к API.

| Режим | Значение |
|---|---|
| `studio-project` | Используются настройки и секреты Studio/проекта |
| `cli-project` | Настройки Studio служат основой; сверху применяются env и параметры CLI |
| `environment` | CLI или фоновый процесс использует конфигурацию окружения напрямую |

При ошибке проверьте соответствие сервиса, модели и протокола. Например, `--service google --model kimi-k2.5` отклоняется до отправки запроса.

Ключи Google Gemini AI Studio работают с OpenAI-совместимым адресом Gemini. InkOS исключает параметр OpenAI `store`, который Google не поддерживает. MiniMax и MiniMax CodingPlan используют официальный OpenAI-совместимый адрес `/v1` и выбирают работающий непотоковый транспорт, если поток сообщает расход токенов, но не возвращает текст. Для `MiniMax-M3*` возвращаемые рассуждения по умолчанию отключены; для M2.x сервис не позволяет их отключить.

Каталог провайдеров содержит адреса, протоколы, модели и правила совместимости для Google Gemini, Moonshot, MiniMax, Zhipu (GLM), Bailian, DeepSeek, SiliconFlow, Volcengine, Tencent Hunyuan, Baidu ERNIE, iFlytek Spark, OpenRouter, kkaiapi, Ollama и CodingPlan. Если `INKOS_LLM_SERVICE` не задана, сервис определяется по базовому URL.

## Первая книга

```bash
inkos book create --title "Последний поезд" --genre other --platform other --lang ru
inkos book list
```

Возьмите идентификатор из результата создания или списка книг:

```bash
inkos write next <book-id>
inkos status <book-id>
inkos review <book-id>
inkos export <book-id> --format epub
```

`write next` записывает следующую главу. Проверка возвращает наблюдения; переписывание и правка остаются отдельными действиями. Язык романа выбирается через `--lang ru`, `--lang en`, `--lang zh` или селектор языка в Studio.

Для англоязычного LitRPG исходный проект предлагает такой пример:

```bash
inkos book create --title "The Last Delver" --genre litrpg --lang en
```

### Законченный рассказ

В чате можно попросить законченный рассказ с заданным числом глав и развязкой. Унаследованный пример CLI:

```bash
inkos short run \
  --direction "modern short fiction marriage reversal evidence-driven heroine" \
  --chapters 12 \
  --chars 1000
```

Файлы сохраняются в `shorts/<story-name>/final/`: `full.md`, `sales-package.md`, `cover-prompt.md` и, при настроенной генерации, `cover.png`. Языковую адаптацию этого режима проверяйте отдельно от поддержки русского романа.

### Отдельная обложка

Для обложки существующего произведения попросите её в чате, указав название, синопсис и визуальное направление. Повторный запуск всей цепочки рассказа для этого не требуется.

Инструмент записывает `covers/<title>/cover-prompt.md` и `covers/<title>/cover.png`. Предварительно настройте сервис обложек и его ключ API на странице моделей. После генерации запрос можно изменить в чате: новая инструкция передаётся как `coverPrompt`, файл запроса обновляется, изображение создаётся заново. Текст произведения при этом не переписывается.

### Открытый мир и ветвящаяся история

Выберите соответствующий пункт в Studio и опишите устройство мира, ход времени, действия персонажей, правила предметов и улик. Например, патруль может занимать час, а обучение — несколько дней; редкость предметов можно показывать материалом и свечением вместо числовой таблицы.

InkOS создаёт мир, персонажей, предметы, улики, отношения, текущую сцену и предложенные действия. Открытый мир принимает свободные действия; ветвящаяся история предлагает варианты выбора. При настроенной генерации иллюстрации персонажей, предметов, улик и сцен отображаются в чате.

## Жанры

В версии 2.0 `--genre` и `--platform` принимают непустую строку. Профессиональную методику задают навыки и ограничения произведения. Ниже примеры жанров из исходного руководства.

| Жанр | Основные механики |
|---|---|
| LitRPG | Числовая система, рост силы и характеристик |
| Progression Fantasy | Рост возможностей; числовая система необязательна |
| Isekai | Различие миров и культур, исследование эпохи |
| Cultivation | Ступени развития и роста силы |
| System Apocalypse | Числовая система и выживание |
| Dungeon Core | Развитие, рост силы, управление территорией |
| Romantasy | Эмоциональные арки, ритм двух точек зрения |
| Sci-Fi | Исследование эпохи, непротиворечивость технологий |
| Tower Climber | Развитие по этажам и рост возможностей |
| Cozy Fantasy | Низкие ставки, спокойный ритм и уютный тон |

В исходных примерах используются также обозначения китайской сетевой литературы: `xuanhuan`, `xianxia`, `urban`, `horror`, `other`. Для русского романа без подходящего профиля используйте `other` и явно опишите жанр в авторском замысле.

## Возможности и ограничения операций

### Обсуждение и действия

Studio Chat создаёт романы, запускает Short и Play, генерирует обложки и редактирует сохраняемые текстовые материалы. Для операций, требующих подтверждения, показывается карточка. Обсуждение само по себе не изменяет произведение.

Все основные способы общения используют общий контур исполнения: Studio Chat, полноэкранный `inkos tui`, внешний `inkos interact --json --message "..."` и явные команды `write next`, `revise`, `review`, импорта и экспорта.

### Проверка и правка

Проверяющий агент сопоставляет материал с запросом автора, каноном, текущим состоянием, планом главы и выбранным навыком проверки. Результат содержит конкретные наблюдения, доказательства и направление исправления. Проверка не выставляет оценку, не отклоняет главу по художественным основаниям и не разрешает автоматическое переписывание. Правка выполняется явно и создаёт прослеживаемую версию материала.

### Анализ стиля

`inkos style analyze` извлекает из образца практическое руководство по стилю с опорой на текст. `inkos style import` привязывает его к произведению для написания и правки. Метод задают выбранные навыки анализа и стилизации.

### Авторские материалы и управление замыслом

`inkos book create --brief my-ideas.md` принимает заметки, описание мира или персонажей. Architect создаёт `outline/story_frame.md`, `outline/volume_map.md`, карточки персонажей и `book_rules.md/json`. Долгосрочное направление сохраняется в `story/author_intent.md`.

У каждой книги есть два документа управления:

- `story/author_intent.md` описывает, какой должна стать книга в целом.
- `story/current_focus.md` задаёт, к чему вернуть внимание в ближайших 1–3 главах.

Направление можно уточнять через Studio, TUI или `inkos agent`. Planner выбирает относящиеся к задаче материалы и сохраняет `story/runtime/chapter-XXXX.intent.md`. Composer записывает фактический контекст и трассу с источниками, уровнями защиты, результатами поиска и сведениями о сжатии.

### Объём главы

`write next` и `revise` используют общий детерминированный учёт длины:

- `--words` задаёт целевой диапазон, а не обещание точного числа слов.
- Китайский текст по умолчанию измеряется в `zh_chars`, английский в `en_words`; русские главы используют подсчёт слов с поддержкой кириллицы.
- InkOS не обрезает текст и не помечает главу неудачной из-за отклонения объёма.
- При выходе за жёсткие границы глава сохраняется вместе с измерениями и наблюдением.

### Продолжение и производные произведения

`inkos import chapters` импортирует готовый роман и восстанавливает структурированное состояние, краткие содержания, зацепки, отношения персонажей и читаемые Markdown-проекции. Поддерживаются заголовки `Chapter N`, собственное правило разбиения и возобновляемый импорт. Затем историю можно продолжить через `inkos write next`.

`inkos fanfic init --from source.txt --mode canon` создаёт фанфик по исходному материалу. Режимы: `canon`, `au`, `ooc`, `cp`. Типизированный импорт канона и навык фанфика сохраняют факты источника и границы знания персонажей. Отдельные способы создания предусмотрены для побочных историй, стилизации и продолжения.

### Фоновая работа и уведомления

`inkos up` запускает цикл написания по расписанию. При обработанных некритических проблемах работа продолжается; когда требуется решение человека, сохраняются результаты для проверки. Поддерживаются Telegram, Feishu/Lark, WeCom и webhook с подписью HMAC-SHA256 и фильтрацией событий. Журнал `inkos.log` имеет формат JSON Lines; `-q` включает тихий режим.

### Протоколы и надёжность

Поддерживаются OpenAI Chat Completions, OpenAI Responses, Anthropic Messages и совместимые адреса. Отсутствующий структурированный результат, оборванный поток или остановка по лимиту вывода обрабатываются как ошибка либо продолжаются до завершения; частичный результат не должен считаться успехом.

Для главы создаётся снимок состояния. Текст, индекс и структурированное состояние сохраняются атомарно. Файловые блокировки и очереди действий предотвращают конкурирующие записи.

Сюжетные зацепки проверяются схемами Zod: `lastAdvancedChapter` должен быть целым числом, а `status` принимает `open`, `progressing`, `deferred` или `resolved`. Изменения JSON проходят `applyRuntimeStateDelta` и `validateRuntimeState` до сохранения. Повреждённая структура отклоняется.

Карточки моделей определяют лимиты вывода. Зарезервированные ключи `llm.extra`, в том числе `max_tokens`, `temperature`, `model`, `messages`, `stream`, исключаются, чтобы не подменять основные параметры запроса.

## Как устроена работа над главой

Главный агент интерпретирует запрос и формирует типизированные действия. Программа выполняет инструменты, контролирует подтверждения и права, управляет состоянием и определяет завершение по реальным файлам и результатам операций. Форматы разделяют эту основу, сохраняя собственные навыки и шаги производства.

| Агент | Задача |
|---|---|
| Radar | Анализ направлений рынка и читательских предпочтений; подключается по необходимости |
| Planner | Выбор авторского намерения, текущего фокуса и памяти; подготовка задания главы с требованиями и запретами |
| Composer | Подбор контекста, правил, документов управления и материалов выполнения |
| Architect | Основа книги: каркас истории, правила, персонажи и документы долгосрочного направления |
| Writer | Написание текста по собранному контексту с учётом объёма |
| Observer | Извлечение девяти категорий фактов: персонажи, места, ресурсы, отношения, эмоции, информация, зацепки, время, физическое состояние |
| Reflector | Подготовка изменения JSON; код проверяет схему и применяет его без изменения исходных объектов |
| Continuity Auditor | Сопоставление главы со структурированным состоянием, документами управления и контекстом |
| Reviser | Явная правка по запросу автора, агента или сохранённым наблюдениям; атомарное сохранение новой версии |

Художественные наблюдения сохраняются отдельно от технической проверки записи. Правка создаёт собственную версию и требует явного действия.

### Долговременная память

| Слой | Назначение |
|---|---|
| `story/state/*.json` | Каноническое структурированное состояние, зацепки, содержания глав; проверка схемами Zod |
| `story/*.md` | Читаемые проекции: `current_state.md`, `pending_hooks.md`, `chapter_summaries.md`, `character_matrix.md` |
| `story/memory.db` | Перестраиваемый поисковый индекс SQLite FTS5/BM25; не источник истины |

Агент проверки сопоставляет главу с состоянием: например, ищет знание, которого персонаж не мог получить, или предмет, утраченный ранее. Settler передаёт полное приращение состояния через типизированный инструмент. Программа применяет и проверяет его, затем строит Markdown-проекции. Поисковые индексы восстанавливаются из канонического JSON; модель семантически выбирает материалы среди кандидатов BM25.

### Документы управления и материалы выполнения

- `story/author_intent.md`: долгосрочный авторский замысел.
- `story/current_focus.md`: ближайшее направление.
- `story/runtime/chapter-XXXX.intent.md`: задача главы, требования, запреты и разрешение конфликтов.
- `story/runtime/chapter-XXXX.context.json`: контекст, фактически выбранный для главы.
- `story/runtime/chapter-XXXX.trace.json`: трасса сборки этого контекста.

Замысел, узлы плана, правила книги и текущая просьба сначала собираются в контекст с определёнными приоритетами. Авторские ограничения и явный запрос управляют действием; план помогает работе, но не отменяет запрос автоматически.

У произведения также есть `book_rules.md`, `book_rules.json`, `outline/story_frame.md` и `outline/volume_map.md`. Профессиональный метод можно переопределить проектным `SKILL.md` с тем же идентификатором. Код агента сохраняет динамическую задачу, контекст полномочий и протокол инструментов.

## Способы работы

### Полный цикл одной командой

```bash
inkos write next my-book
inkos write next my-book --count 5
```

Последовательность: планирование → сборка контекста → написание → наблюдения проверки → атомарное сохранение. Пять глав пишутся последовательно. Художественные замечания не превращают сохранённую главу в технически неудачную.

### Явные операции

```bash
inkos write next my-book --count 3
inkos revise my-book 31 --json
inkos review my-book --json
inkos export my-book --format epub
```

Команды задают уже выбранное действие. Запрос на естественном языке проходит через общий исполнительный контур и возможности текущего профиля произведения.

### Запросы на естественном языке

```bash
inkos agent "Напиши LitRPG-роман, где главный герой — целитель в мире подземелий"
inkos agent "Напиши следующую главу: сосредоточься на битве с боссом и распределении добычи"
inkos agent "Создай фэнтези о развитии мага, которому доступно только одно заклинание"
```

Агент может подключать навыки, изучать произведения, предлагать создание, писать, проверять и править в пределах разрешённых возможностей. Завершение подтверждается `ActionResult` и версиями сохранённых материалов.

### Интерактивный режим Studio

«Открытый мир» и «Ветвящаяся история» запускаются без предварительного создания книги. Опишите правила мира, время, самостоятельность персонажей и значение предметов или улик. Состояние сохраняется локально для продолжения сеанса.

## Подключение внешнего агента и навыков

В `skills/SKILL.md` находится инструкция использования InkOS внешним агентом. После сборки доступна общая точка входа:

```bash
inkos interact --json --message "continue the current book, but keep the pacing tighter"
```

Она использует тот же исполнитель разговоров, что и TUI. JSON содержит ответ и сеанс, но факт выполнения следует проверять по результатам инструментов и файлам. Доступные явные операции перечислены ниже и в `inkos --help`. Исторические команды планирования из старых руководств не следует считать актуальным CLI версии 2.0.

Формат навыков соответствует стандартному `SKILL.md`. Навык даёт профессиональные инструкции и статические справочники, но не дополнительные права исполнения.

- Поддерживаются проектные `skills/`, `.agents/skills/`, пользовательские `~/.agents/skills/` и `~/.openclaw/skills/`.
- В Studio можно импортировать папку с `SKILL.md` и справочниками; она сохраняется в `.agents/skills/` проекта.
- `INKOS_SKILL_DIRS=/abs/path/to/skills` принимает папку одного навыка или каталог нескольких. Для нескольких путей используется системный разделитель.
- `@skill-id` явно назначает навык текущему запросу.
- Без явного назначения агент сам решает, вызывать ли `use_skill`. Тип сеанса, ключевые фразы и поиск подстрок навыки не включают.
- Скрипты внешних навыков автоматически не выполняются. Навыки не обходят разрешения инструментов и подтверждения.

Минимальный формат из исходной документации:

```md
---
name: Detective Play
description: Detective evidence and suspect-board play.
---
Use evidence chains; do not turn clues into generic atmosphere.
```

## Справочник команд

Во всех примерах `inkos` означает локальную сборку этого форка, запущенную способом из начала руководства.

| Команда | Назначение |
|---|---|
| `inkos init [name]` | Создать проект; без имени — в текущем каталоге. Для русского проекта добавьте `--lang ru` |
| `inkos book create` | Создать книгу: `--genre`, `--chapter-words`, `--target-chapters`, `--brief`, `--lang en/zh/ru` |
| `inkos book update [id]` | Изменить объём главы, число глав, состояние или язык |
| `inkos book list` | Показать книги |
| `inkos book delete <id>` | Удалить книгу и данные; `--force` пропускает подтверждение |
| `inkos work` | Просмотреть произведения, материалы, версии и эпизоды выполнения |
| `inkos chapter` | Управлять сохранёнными главами |
| `inkos auto [id] <target-chapter>` | Писать до заданного номера главы |
| `inkos translate` | Переводить и локализовать произведения |
| `inkos write next [id]` | Написать следующую главу; `--words`, `--count`, `-q` |
| `inkos write rewrite [id] <n>` | Переписать главу с восстановлением снимка; `--force` пропускает подтверждение |
| `inkos revise [id] [n]` | Править выбранную главу |
| `inkos agent <instruction>` | Выполнить запрос на естественном языке |
| `inkos review [id]` | Показать сохранённые наблюдения проверки |
| `inkos status [id]` | Состояние проекта |
| `inkos export [id]` | Экспорт: `--format txt/md/epub`, `--output <path>` |
| `inkos radar scan` | Исследовать направления рынка для новой книги |
| `inkos fanfic init` | Создать фанфик: `--from`, `--mode canon/au/ooc/cp` |
| `inkos short run` | Подготовить законченный рассказ и сопроводительные материалы |
| `inkos forecast create/show/select` | Создать, проверить и выбрать неканонический вариант продолжения; выбор сохраняет только план |
| `inkos interact` | Вход для внешнего агента: `--json`, `--message`, `--book` |
| `inkos config set-global` | Глобальная конфигурация CLI/фонового процесса в `~/.inkos/.env` |
| `inkos config show-global` | Показать глобальную конфигурацию |
| `inkos config set/show` | Читать и менять настройки проекта |
| `inkos config set-model <agent> <model>` | Отдельная модель агента: `--base-url`, `--provider`, `--api-key-env` |
| `inkos config remove-model <agent>` | Удалить отдельное назначение модели |
| `inkos config show-models` | Показать маршрутизацию моделей |
| `inkos doctor` | Проверить конфигурацию, совместимость и подключение к API |
| `inkos detect [id] [n]` | Проверка внешним ИИ-детектором; `--all`, `--stats` |
| `inkos style analyze <file>` | Проанализировать стиль образца |
| `inkos style import <file> [id]` | Привязать стилевое руководство к книге |
| `inkos import canon [id] --from <parent>` | Импортировать канон исходного произведения |
| `inkos import chapters [id] --from <path>` | Импортировать главы для продолжения; `--split`, `--resume-from` |
| `inkos analytics [id]` / `inkos stats [id]` | Наблюдения, объёмы глав и расход токенов |
| `inkos update` | Обновление исходного npm-пакета; для форка используйте инструкции `git pull` выше |
| `inkos` / `inkos studio` | Запустить Studio; `-p` задаёт порт, по умолчанию 4567 |
| `inkos tui` | Запустить полноэкранный TUI |
| `inkos up / down` | Запустить/остановить фоновый процесс; `-q`, журнал `inkos.log` |

Если книга в проекте одна, `[id]` определяется автоматически. `write next` принимает `--context` для направления главы и `--words` для объёма. В Studio можно просмотреть намерение, контекст и трассу главы.

Разовые настройки модели: `--service`, `--model`, `--api-key-env`, `--base-url`, `--api-format <chat|responses>`, `--stream`, `--no-stream`.

```bash
inkos write next --service google --model gemini-2.5-flash
inkos up --service moonshot --model kimi-k2.5 --api-key-env MOONSHOT_API_KEY
```
